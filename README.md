# Independent Workflow Kit

0.4.0 移除直连 App Server 的驱动。后台只通过 Codex 原生 queue 提交事件，桌面 App 管理会话、执行和审批；已入队不等于已执行。事件账本、可修订计划和原有守卫保留。启用前必须实际验证桌面 App 的空闲和忙碌队列消费，步骤见 [REACTIVE.md](REACTIVE.md)，本次实测范围见 [NATIVE_QUEUE_VALIDATION.md](NATIVE_QUEUE_VALIDATION.md)。

下面的四角色安装入口继续兼容实例初始化和未迁移任务。active 任务使用 REACTIVE.md 的主对话与负责人协议，不再经过触发器/协调器的十分钟接力；原控制对话可以保留。

这是面向另一台 macOS 电脑和另一个项目的独立部署包。它包含本地 Node.js 运行时、Codex 角色说明、安装命令和测试。没有 npm 依赖。

每份安装拥有独立的 instance ID、四个角色绑定、SQLite 队列、任务账本和决策中心。运行时按本目录定位数据，项目和外部渠道从 instance.json 读取。它不连接原来那台电脑，也不包含原项目任务、历史对话、审批授权、登录状态或构建缓存。

## 直接发给 agent 的安装 prompt

在目标 Mac 上用 Codex 打开解压后的工作流目录，复制下面整段，只需填写项目名称和项目绝对路径。其他配置可以先留空；核心流程安装完成后再按项目授权接入外部工具。该 prompt 明确请求创建必要角色和定时任务，agent 不应只停在方案。

```text
请使用这份工作流项目的代码，在当前 Mac 的 Codex 中，为下面的项目实际搭建一套独立工作流，完成安装、原生绑定和验证；不要只给方案或让我逐步手工执行。

项目名称：<填写项目名称>
项目目录：<填写该项目在本机的绝对路径>
工作流源码目录：当前打开的 workflow-kit 目录；如果不在当前目录，先定位这份 README 所属的独立部署包。
可选配置：未提供时采用包内默认值；GitHub 仓库可从上述项目的 remote 核验。Slack 送审、Notion 页面写入、自动转 ready、自动合并、会前准备、云资源管理默认不启用。若我在本次请求另行给出明确授权和配置，按该范围接入。

这条请求明确授权你为这个项目创建或复用以下四个角色对话：工作决策中心、后台协调、触发器、工作流维护；置顶本实例的工作决策中心；创建一条每十分钟运行的触发器定时任务。可以将当前安装对话复用为维护角色，但四个角色不能共用同一对话。不要额外创建示例工作、重复角色或第二套定时器。

请按以下要求执行：

1. 先读 README.md、START-HERE.md、POLICY.md、QUEUE_PROTOCOL.md、ROLE_PROMPTS.md、runtime/README.md 和项目适用的 AGENTS.md。检查本机工具、支持 node:sqlite 的 Node.js，以及 Codex 原生项目、对话、置顶和定时任务能力。优先复用已有工具和环境。仅当缺失必需的项目路径、授权范围或原生能力时集中询问一次；已明确授权的安装步骤无需逐步确认。

2. 为本项目使用独立安装目录、instance ID、配置和账本。先查是否已有匹配实例：有则核验并补齐；没有才运行 workflow.mjs init。不得清空、覆盖或导入其他实例的任务、数据库、频道、审批授权、登录状态、VM 租约和构建缓存，也不得打断已有作业。发现当前目录是另一项目的运行实例时，先从干净源码准备新的独立目录。

3. 使用支持的原生工具核验本项目的实际 project ID，按 ROLE_PROMPTS.md 创建或复用四个角色。将 INSTANCE_ROOT、INSTANCE_NAME 等占位符替换为真实值，再发送角色 prompt。保留我选择的模型、推理强度和权限；模型设置统一保存到 instance.json 的 models。除非我明确选择，不自行降级或升级模型。若某个协调角色另选轻量模型，执行任务仍保留自己的默认模型配置。

4. 创建后用原生列表回读各角色的 ID 和项目归属，保存真实证据，再用 workflow.mjs bind 绑定。把本实例决策中心置顶。不能把创建 ACK 当成归属核验，不能伪造 ID 或修改 App 内部数据库来完成绑定。安装期间可以初始化本实例配置；安装后 registry.json、decisions.json 和可选 Notion 投影由后台协调唯一维护。

5. 通过支持的 automation_update 能力创建或复用唯一的十分钟触发任务，目标为本实例触发器，先保持 PAUSED。使用 ROLE_PROMPTS.md 的触发器模板，配置无变化时静默。触发器只做有界状态检查和空闲时投递；协调器、决策中心、维护对话不再另挂周期心跳。北京时间每天 05:00 的审视由同一队列准入，不新增另一个定时器。

6. 接入本项目已有工作对话，之后自动发现本项目的新工作。逐项核验真实用户目标、原负责人、当前任务／作业状态和已有驱动，禁止重复派发或接管其他项目。协调按固定短批次运行；执行结果、剩余目标、具体下一步或真实阻塞必须持久化。区分已投递、实际开始和完整完成；对丢失事件与漏接续使用已有恢复逻辑，不重复启动健康作业。

7. 我以后主要在本实例工作决策中心交流。所有需要我选择的事项只使用对应的稳定 T 任务编号和问题主题，不新增 D 编号，给出建议、影响和证据，并维护持续更新的待决清单；未启用 Notion 时使用本地 decisions.json。中心只展示必要决策、请求的答案和重要完成，不发周期进度。新的技术追问交给原执行负责人，中心不自行展开实现。只有整个目标验收、交付和资源收尾都完成后，才归档对应执行对话。

8. 保留包内个人规则：中文交流、表格英文、不设固定任务数量上限、真实资源和唯一负责人约束、最小而充分的验证、北京时间 03:00–09:59 不送审 PR。开发、测试、修复和内部 review 可以继续；待送审项持久暂存，10:00 后由已有协调轮次重新核验。不得替我回复 Slack、发外部 comment、提交 review 或请求 reviewer。默认关闭的外部集成使用本地成果交付，不把它们报成阻塞，也不套用其他项目的频道或审批人。

9. 若本次明确启用了可选能力，完成其真实接入：为本项目配置已授权的仓库／Linear／Slack 来源；Notion 仅写指定页面；PR 仅向指定频道发送规范链接并按指定审批人、当前 head、必需 CI 和仓库规则合并；会议按指定日历和排除项提前 45 分钟准备中文简报＋英文要点；云任务和 Rust 缓存按本机配置及已安装 skills 初始化。缺少这些参数时先完成核心工作流，清楚列出未启用项，不猜测、不复制原实例资源，也不凭空新增周期任务。

10. 完成验证再启动调度：运行 doctor 和包内隔离测试，确认重复安装不会覆盖数据、队列可持久化、重复事件不会重派、项目边界和送审窗口有效；通过真实原生快照核验四个角色、置顶状态、定时任务目标和空闲检查。禁止用真实 Slack、PR 转 ready、合并、云资源创建或产品任务作为安装测试。核验通过后标记 setup_complete，再将唯一触发器设为 ACTIVE，回读并保存安装回执。

请持续完成所有已授权且可执行的步骤。只有真实缺少必要信息或遇到必须由人完成的原生登录验证时才停下说明具体阻塞；不要把排队、提案或创建回执说成安装完成。

最终给我：工作决策中心链接、实例目录、已启用的项目和来源范围、各角色的实际模型配置、唯一触发器的真实状态、验证结果，以及尚未启用或确实受阻的可选功能。说明我之后如何查看待决事项、添加本项目工作、暂停和恢复调度。
```

这段 prompt 依赖 agent 能读取本目录的源码和文档，并具备相应的 Codex 原生工具。只有普通聊天能力的 agent 无法凭 prompt 创建真实对话或定时任务。标准安装步骤和原生回读要求见 [START-HERE.md](START-HERE.md)。

## 在新电脑使用

可以将本仓库 clone 到新电脑，也可以使用独立压缩包。配置和任务账本属于每台电脑自己的实例；Git 只同步源码和规则，忽略本地实例绑定、数据库、运行记录及凭据文件。

1. 将整个目录放在新电脑的固定位置，安装或使用支持 node:sqlite 的 Node.js。本包验证环境为 Node.js 23.11.0。
2. 在 Codex 打开这个目录，复制本 README 上面的安装 prompt，填写新项目的实际目录。
3. 安装任务会初始化本地状态，使用 Codex 原生工具创建或核验项目与角色、置顶该实例的决策中心，并配置一条十分钟触发任务。CLI 本身不创建原生对话或定时任务。
4. 后续主要和该实例的决策中心交流。另一个电脑上的工作流继续独立运行。

也可以先在终端检查：

```sh
node workflow.mjs
node workflow.mjs test
node workflow.mjs init --name project-b --project-root '/absolute/path/to/project'
node workflow.mjs doctor
```

项目目录必须真实存在。init 不会覆盖已有任务或数据库；重复安装请使用新的解压目录。doctor 会准确区分本地环境、角色绑定与已记录的原生安装结果；它不能代替 Codex 原生工具检查连接器和定时任务的实际状态。

## 可复用部分与项目独立部分

复用：队列去重、阶段续接、恢复、短批次协调、必要决策集中、完成后归档、每日审视，以及少做无必要验证的工程准则。

保留的个人偏好：中文交流、表格英文、默认继承用户所选模型与权限、不打断健康作业、没有固定任务数量上限、北京时间 05:00 审视、03:00–09:59 不送审。首版沿用这些时间规则，不能只编辑任意时区字段而假设运行时支持了新的时区政策。

独立配置：项目目录、原生 project ID、四个角色 chat ID、仓库列表、GitHub 身份、可选 Slack 频道、合并审批人、Notion 页面。外部渠道、ready 转换和自动合并默认关闭；只有新项目的真实授权和对应绑定齐全后才启用。当前项目的频道和审批人不会迁移。

会前准备、云资源管理和构建缓存是可选扩展，首版未自动启用。新电脑可使用本机已安装的相关 skills 与连接器，并根据新项目的日历、云账户、机器配置接入；不会复制原来的会议、VM、租约或缓存容量。

## 模型选择

instance.json 的 models 是唯一模型配置入口。default="inherit"、角色值为 null 表示沿用用户所选模型与推理配置。只有用户明确选择后，安装或后续配置任务才将具体值传给支持该参数的原生工具，不修改原生权限。

以后若明确为协调器选择较轻量的模型，应同时保存执行任务的默认模型和推理配置，避免新工作误继承协调器的角色配置。已有执行对话始终保留自己的选择。

触发器只执行有界检查和投递，适合评估轻量模型。协调器还要判断任务授权、归属、依赖和交付条件，适合评估中档模型；复杂实现与疑难 review 继续由执行任务承担。本包不擅自降级任何角色，也不内置可能过时的模型名称或价格。

## 运行边界

本地脚本负责记录和检查，Codex 负责推理与调用工具。需要本机文件的调度要求电脑和原生宿主运行。旧模式不安装 daemon；新运行时可按 REACTIVE.md 显式启动或安装本机 LaunchAgent。没有云服务或跨机器同步系统。

不要同步两份实例的实时 SQLite 文件。它们处理不同项目；如果将来需要转移同一项运行工作，应另做可验证的状态交接。复用源码升级时保留 instance.json、账本、回执和产物，不能重新初始化已有实例。

原生工具、连接器和权限需要在目标电脑核验。本地 guard 是工作流约束，不是对任意直接外部调用的系统级拦截器。

这是可独立安装的 0.4.0 源码包，不含自动更新服务。后续引擎升级应发布新版本，在独立实例测试后只更新代码和规则，保留各自的配置与状态。

## 文件

runtime/ 是通用运行时；workflow.mjs 是安装和检查入口；POLICY.md 与 QUEUE_PROTOCOL.md 规定角色和交付流程；ROLE_PROMPTS.md 提供原生角色模板；templates/preferences.json 保存可复用偏好；PROVENANCE.json 保存源代码快照哈希；VALIDATION.json 保存本包验证结果。

安装后生成的 instance.json、registry.json、decisions.json、SQLite、batches/ 与 observations/ 属于该实例自己的数据，不属于可复用发布包。

0.1.4 对已启用的 PR 流程增加完整反馈采集与当前提交判读，详见 REVIEW_FEEDBACK.md。连接器不能提供完整分页／commit 绑定时可使用已登录 gh 的只读采集器；未启用 GitHub 工作流时无需 gh。

0.1.5 修复应用重启后已结束对话因 `notLoaded` 被一律拒绝接续的问题；仍要求真实任务、作业和权限证据，详见 LIVENESS_RECOVERY.md。

0.1.6 支持可选的独立成果页面。用户需要时按 OUTCOMES.md 配置，默认不启用，也不增加定时器或 Notion 必需依赖。绑定和成果数据保留在本实例，不提交到仓库。
