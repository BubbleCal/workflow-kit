# Current workflow runtime

The native owner loop is defined in OWNER_CONTINUATION.md and POLICY.md.
With the human-authorized owner_autonomy policy enabled, use `runtime work`:
start once, work continuously, and record progress or a genuine stopping outcome.
The runtime supplies revisions and turn bookkeeping. A phase result is not goal
completion. Existing `runtime op` clients remain valid during migration.

## Work, delivery and real waits

The original owner investigates, experiments, implements and validates the accepted
goal inside existing resource/scope authority. A module boundary or ordinary
technical choice does not require a new approval. Keep independent work moving
while an external action waits. Preserve actual pauses, assessment-only limits,
human decisions, expected-head/branch ownership and production commitments.

PR/notification/merge operations use OWNER_DELIVERY.md and the existing control
API at the actual external boundary. A metadata, Notion or notification failure
does not stop independent engineering. Complete source/feedback and real action
receipts remain required; do not retry an uncertain external effect blindly.

OWNER_WAITS.md governs subscriptions and owner-reported next_action_at. Runtime
collectors refresh exact registered sources and publish meaningful changes. A
pending/running refresh or evidence expiry is not an owner wake. Time windows,
pauses and true human-only waits retain their guards and coalesce later inputs.

## Current transport

MESSAGE_TRIGGER.md governs runtime-authored immutable messages and the dedicated
native trigger. Native readback verifies the exact delivery and actual turn.
For ordinary tasks with owner_autonomy enabled, the trigger records begin after
that proof, so the owner need not repeat it. Without that observation the owner
can supply one real proof through work start. Terminal/failed/no-op observations
never become invented active execution. Discovery and maintenance retain their
specialized batch/setup protocols.

Existing accepted/uncertain native queue receipts remain unchanged and are not
converted into duplicate sends. CLI native-queue installs remain supported. The
queue transport only targets its verified local backend; reading a chat alone
does not load it. Official idle-only loading remains subject to actual user input
inactivity and its configured threshold (ten minutes in Yang's instance). Agents
never issue their own UI navigation to force a thread to run.

## Installation and compatibility

Follow START-HERE.md and WORK_TASKS.md for instance registration. Preserve the
verified native project/thread/cwd, original owner, model and permissions.
Native queue capability verification still uses actual same-host idle/busy trials:
`runtime probe`, then `runtime queue-verify --file <actual-proof.json>`.
A probe alone proves no consumption. The actual receipt/native proof schema lives
in runtime/native-queue.mjs; queue-verify rejects mismatched machine/CLI/evidence.

`runtime init` is only for the documented initial migration. It preserves existing
receipts and does not authorize task resumption. Do not re-init a live instance or
replace its databases. Owner/task mode changes use the existing guarded API.
Only workflow runtime may be reloaded for workflow fixes; preserve App, native
owner turns, builds, benchmarks, resources and in-flight receipts.

Use runtime service install/status and runtime run for the existing daemon.
No extra coordinator, heartbeat or timer is needed. Main receives actual user
questions/decisions/completions; discovery owns source intake and authorized
owner creation; original owners deliver their own work. Scheduled maintenance
continues under NATIVE_SERVICES.md and daily-review/config.json.

## Shared facts and outcomes

Registered PR artifacts feed the shared source poller without stealing another
owner's PR. GitHub job waits use the exact registered job collector and durable
wait-observation outbox. Generic sources need real producers; stale unknowns are
routed to existing maintenance, never invented terminal facts. SourceRate enforces
the existing quota/concurrency budget and provider pause across shared reads.

Finite results and useful followups use RESULT_FOLLOWTHROUGH.md. A report is
separate from whole-goal acceptance. Completion delivery follows
TASK_COMPLETION_DELIVERY.md before archival. Retain source/head/environment
provenance, regressions and limitations, and reuse existing same-state evidence.

For exceptional low-level recovery, preserve the actual failed/queued turn and
follow OWNER_RECOVERY.md. A new human turn and a trigger/queue execution have
different proofs; do not fabricate a relay or claim an old queue was consumed.
